Guia rápido

Passos (a "receita")

Cada ação (filtrar, ordenar, mascarar...) é um "passo". A lista de passos aplicados fica registrada e pode ser salva como uma receita — um arquivo `.json` que reaplica a mesma sequência em outro arquivo depois, sem refazer nada na mão.

Salt

A "senha" da anonimização. O mesmo valor de entrada + o mesmo salt sempre gera o mesmo código — é isso que permite cruzar duas tabelas mascaradas separadamente (mesmo CPF em ambas vira o mesmo código). Trocar o salt muda todos os códigos. Use pelo menos 16 caracteres aleatórios (o botão de dado ao lado do campo gera um automaticamente) e guarde em lugar seguro.

Chave de criptografia (key)

Diferente do salt. O salt protege os valores dentro da tabela; a key criptografa o arquivo `.dlk` inteiro — sem ela, o arquivo não abre de jeito nenhum, nem para ver os nomes das colunas. São dois segredos independentes: perder um não compromete o outro.

Hash × Criptografia reversível

Hash não tem volta — é isso que a lei chama de dado "anonimizado" (deixa de ser considerado dado pessoal). Criptografia reversível pode ser desfeita por quem tem o salt certo — é "pseudonimização": mais seguro que o valor original, mas ainda é dado pessoal para efeitos legais. Use hash quando não precisar mais do valor original; use a reversível só quando alguém autorizado for precisar recuperá-lo depois.

O formato .dlk

Um arquivo próprio do datalock Studio — pense nele como "um Parquet melhorado". Guarda uma ou várias tabelas dentro de um único arquivo, com ou sem criptografia. Útil para mandar várias planilhas relacionadas de uma vez, ou para arquivar um resultado sensível protegido por senha.

Abas

Cada tabela aberta (um arquivo, uma planilha de um Excel com várias, uma tabela de banco) vira uma aba própria, com sua própria lista de passos — como abrir várias planilhas ao mesmo tempo.
